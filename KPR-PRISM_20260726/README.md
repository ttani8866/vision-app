# KPR-PRISM ライト版「PR戦略プランナー」

共同ピーアール株式会社のPR企画・提案業務を支援するAIアシスタント（ライト版）の配布物一式。
一言の案件概要と手元資料から、共同ピーアールらしさを貫いた**「提案の骨子」**を一本道で作成する。

## 背景

- 当初構想（フル版）は6職種のAIエージェント×約20スキル。PR実務を2領域・10業務・64項目に分解した業務台帳と、当社の思想を判断基盤とする設計だった
- 社内レビュー（2026年7月）で「社員が使うときはとにかくシンプルに」「メインはライト版」「らしさはより具体的に」「案件データを取り込めるカスタマイズ性」の方針を確定
- これを受け、**PR戦略プランナー1職種×10スキルのライト版を先行実装**したのが本フォルダ。フル版は設計凍結して保管中（`20260718検証/KPR-AgentOS/`）。ライト版で検証済みのスキルはフル版の資産になるため、二重開発にはならない
- AIの成果物は骨子まで。「おもしろいか」「世に出してよいか」の価値判断は必ず人間が行う

## フォルダ構成

```
├── README.md                    # 本ファイル（構成概要・背景・解説）
├── CLAUDE.md                    # AI向け統制の正本（起動方法・壊してはいけないもの）
├── SETUP_GUIDE.md               # 導入・使い方ガイド（人間向け操作説明）
├── .claude/
│   ├── commands/kpr.md          # エージェント本体（/kprコマンド＝PR戦略プランナーの指示書）
│   ├── skills/                  # スキル10本（下表）
│   └── settings.json            # 機械的統制（push/再帰削除=拒否、外部送信系=確認制）
├── templates/
│   ├── 骨子テンプレート.md       # 骨子の固定フォーマット（11欄）
│   └── レビュー評価表.md         # テストローンチ用の採点表（5観点）
└── clients/
    └── _雛形_案件フォルダ/       # コピーして「○○社_△△案件」にリネームして使う
        ├── brief.md             # 与件メモ（6項目フォーマット）
        ├── data/                # 資料置き場（形式問わず）
        └── output/              # 生成された骨子の保存先（版管理）
```

## エージェント：PR戦略プランナー

`.claude/commands/kpr.md` に定義された単一エージェント。`/kpr <案件概要>` で起動する（直接依頼でも同じ指示書で動く）。

- **一本道フロー**：入力 → ①与件整理・分析 → ②骨子作成 → ③出力前チェック → 出力（骨子1本）
- **質問は最大3つ**（与件の「課題」「予算」が埋まらないときだけ）。埋まらない欄は骨子末尾の「未確定事項」へ
- **出力は骨子1種のみ**（`templates/骨子テンプレート.md` の11欄固定様式。既報チェック実施記録の欄を含む）

### 判断基盤「らしさ」8項目（教本「企業広報」から抽出）

エージェント定義に内蔵された、共同ピーアールのPR思想。各項目は「骨子のどの欄に現れるか」までセットで定義してあり、抽象論ではなく出力の形として現れる。

定義の正本は `.claude/commands/kpr.md` §1（定義を変えるときはそのファイルだけを更新する）。項目名のみ以下に列挙する。

1. ゴールの書き方（誰のどんな信頼・評判を作るかまで書く）
2. メディアファースト（記者が取り上げたくなることから逆算。想定見出し必須）
3. メディアリレーションズ（掲載保証と読める表現の禁止・媒体特性別の書き分け）
4. ステークホルダー（メディアは増幅装置でありゴールではない）
5. 事実立脚（裏付けのない記述は載せない・数値には出典）
6. ニュース価値（最低条件4つ＋発表条件の推奨）
7. PR SPOTLIGHTS（各ストーリー案にタグを明記）
8. 社会性の翻訳と3S（社会文脈欄と「なぜ今か」が必須）

※PR SPOTLIGHTS 10視点の定義表のみ、正本は `.claude/skills/KPR-Kikakusho-Sakusei/reference/pr-spotlights.md`。

## 統制（壊してはいけないもの）

1. **クライアント機密の共通側への混入** — 案件実データは `clients/` に閉じる。スキル・定義・テンプレ（共通側）へ書き込まない
2. **事実未確認・「掲載保証」と読める表現の提出物への混入** — 見つけたら出力せず停止して人間に確認

詳細は `CLAUDE.md`（AI向け統制）と `.claude/settings.json`（機械的強制）を参照。
