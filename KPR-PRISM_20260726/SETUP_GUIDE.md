# SETUP GUIDE — KPR-PRISM ライト版「PR戦略プランナー」

このフォルダ一式が、そのままライト版の配布物です。導入と使い方を以下にまとめます。

## 1. 導入

1. このフォルダ（`KPR-PRISM_20260726` 一式）を、利用者のPCの任意の場所にコピーする
2. Claude Code（またはCowork）でこのフォルダを開く
3. **セッションを一度再読込する**（`.claude/` 配下のコマンド・スキルはセッション開始時に読み込まれるため、コピー直後は認識されません）
4. フォント不要・外部依存なし。スキル10本は同梱済み

## 2. 使い方（基本は1コマンド）

```
/kpr 〈案件の概要ひと言〉
```

例：`/kpr A社の新サービスの戦略提案を作りたい。オリエン資料はclients/A社_新サービス提案/data/に入れた`

- コマンドを使わず「A社の提案骨子を作って」と直接依頼しても、同じフロー（`.claude/commands/kpr.md`）で動きます
- 出力は**骨子1本**（`templates/骨子テンプレート.md` の11欄固定様式。既報チェック実施記録の欄を含む）
- 途中の質問は最大3つ。埋まらない項目は骨子末尾の「未確定事項」に整理されます

## 3. 案件データの渡し方（案件フォルダ方式）

1. `clients/_雛形_案件フォルダ/` をコピーして `clients/○○社_△△案件/` にリネーム
2. `brief.md` の与件6項目を埋める（未確定は「未確定」でOK）
3. `data/` に資料を放り込む（形式問わず・整理不要）
4. `/kpr` で案件フォルダ名を伝える
5. 生成された骨子は `output/` に版管理で保存（2回目以降は前回骨子を踏まえて改訂）

**機密ルール**：クライアント実データは案件フォルダに閉じます。スキル・テンプレート（共通側）へ書き込まれることはありません。

## 4. 骨子承認後の実務展開

骨子が承認されたら、成果物名を挙げて依頼すると対応スキルが起動します。

| 依頼例 | 起動スキル |
|---|---|
| 「この骨子でプレスリリースを書いて」 | prworks-pressrelease |
| 「ニュースレターにして」 | prworks-newsletter |
| 「取材案内状を作って」 | prworks-annaijo |
| 「メディアリストを起こして」 | prworks-medialist |
| 「発表会の進行台本を」 | prworks-daihon |
| 「運営マニュアルを」 | prworks-unei-manual |
| 「実施報告書をまとめて」 | prworks-houkokusho |

## 5. テストローンチ時のレビュー

`templates/レビュー評価表.md` を使い、5観点（使える度・らしさ・事実性・時間・シンプルさ）で採点してください。改善点は評価表の自由記述欄へ。らしさ定義・スキルの修正に直結させます。

## 6. スキルの増補・修正

- スキルは `.claude/skills/<スキル名>/SKILL.md` の公式形式。新スキルは同じ形式でフォルダを追加
- **PR SPOTLIGHTSの定義を変えるときは、正本 `.claude/skills/KPR-Kikakusho-Sakusei/reference/pr-spotlights.md` だけを更新**（他ファイルに定義を複製しない）
- 「らしさ」の定義は `.claude/commands/kpr.md` の §1 に内蔵。変更はこのファイルのみ

## 7. 統制（settings.json）

`.claude/settings.json` で、公開リポジトリへのpush・再帰削除を機械的に拒否（deny）、外部送信系コマンドを確認制（ask）にしています。運用上煩わしい場合は、利用者の判断で `ask` の行を削除して調整してください（`deny` の削除は非推奨）。
