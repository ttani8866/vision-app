# Cursor と Claude Code の使い分け

講座前提（「Cursor 上でフォルダを開き、ターミナルから Claude Code」）と整合するよう、予習前のやりとりで整理した内容。

## ざっくりした違い

| 場所 | 何が動くか |
|------|------------|
| **ターミナルで `claude`** | インストールした **Claude Code（CLI）** が動く |
| **Cursor のチャット** | **Cursor の AI（Composer 等）** が動く |

「ターミナルで Claude はつながる」ことと「Cursor のチャットが同じバックエンドか」は **別**。

## ターミナルの Claude Code が向いていること

- **リポジトリ／フォルダ全体**を触る作業（複数ファイル、一気に実装・リファクタ）
- **シェルとセット**の作業（`git`、ビルド、テストをその場で回す）
- **長い文脈**をそのセッションに載せたいとき（契約・設定・モデルに依存）
- ターミナルに居座りながら **「このプロジェクトをこうしたい」**を続けるスタイル

## Cursor のチャットが向いていること

- **エディタと一体**で進めたい（開いているファイル、選択範囲、診断に沿った修正）
- **Cursor 専用の仕組み**（ルール、`.cursor`、インライン編集の流れ）を使いたい
- **短く何度も**質問・相談（用語、設計、コードの読み方）
- **すでにコンテキストを持っている会話**の続き

## 重複を減らすコツ

- 同じ作業を **両方で同時に**走らせない（指示の食い違い防止）
- **メインはどちらか**を決め、もう一方は補助にすると整理しやすい

講座当日は「Cursor でフォルダを見ながら、ターミナルで Claude Code」と**両方触る前提**なので、「役割が違う」だけ押さえておけばよい。
