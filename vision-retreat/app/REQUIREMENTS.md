# Strength Vision Web アプリ 要件定義書

## 1. 文書の位置づけ

本書は、`vision-retreat/app`（Vite + React）として実装されている「Strength Vision — 強みと目標の羅針盤」Web アプリケーションに対する要件定義である。実装の追加・改修時の判断基準とする。

## 2. システム概要

### 2.1 目的

経営者ビジョン合宿などの場面で利用者が、四つの才能軸（ギフト）に基づく自己理解と、事業・人・個人の目標たたきを一連のフローで得られるようにする。星座風の背景演出のもと、診断から目標案、画像生成用プロンプトまでをブラウザ内で完結させる（画像生成本体は外部ツールへコピーして実行）。

### 2.2 名称・表記

- プロダクト名（英字）: Strength Vision
- キャッチコピー: 強みと目標の羅針盤
- イベント文脈: 経営者ビジョン合宿
- 診断パートの呼称: Gift Discovery

### 2.3 技術スタック

- フロントエンド: React 19、Vite 8
- スタイル: グローバル CSS（ダークテーマ、グラスモーフィズム風カード）
- オプション連携: Anthropic Messages API（開発時は Vite プロキシ経由）

## 3. 利用者と利用シーン

| 利用者 | シーン |
|--------|--------|
| 合宿参加者（経営者） | 当日〜合宿後、自己理解と目標言語化、イメージトレ用プロンプト取得 |
| ファシリテーター | 同一アプリを投影・共有しながら進行（想定） |

## 4. 機能要件

### 4.1 画面遷移（ステップ）

アプリはクライアントサイドのステップで状態を管理する。概略は以下のとおり。

| ステップ | 画面の目的 |
|----------|------------|
| 1a 表紙 | アプリ表紙。正式タイトル・説明・「診断をはじめる」 |
| 1b 設問 | Gift Discovery。全設問を順に表示し、1問1選択で回答 |
| 2 結果 | レーダー、4領域スコア、プロフィール型、総括、集計根拠の開示 |
| 3 ざっくり目標 | 事業・人・個人の自由記述（空欄可） |
| 4 目標案一覧 | カテゴリ別の目標リスト（編集可）。いずれかを選んで次へ |
| 5 画像プロンプト | 英語プロンプト表示・コピー・再生成 |

表紙は初回および「診断をやり直す」実行後に再表示する。

### 4.2 表紙（表紙画面）

- 英字ブランド、和文メインタイトル、サブコピー、プログラム名、リード文、設問数に連動したメタ表記を表示する。
- 背景は既存の星座風パーティクル（固定レイヤ）を維持する。
- 「診断をはじめる」で設問フローへ移行する。

### 4.3 Gift Discovery（設問）

- 設問セットは `data.js` の `QUESTIONS` で定義され、設問数は `STRENGTH_SURVEY_TOTAL`（= 配列長）と一致する。
- 各設問は `weight`（省略時 1）と複数 `options` を持つ。各オプションは `domain`（四領域のいずれか）を主回答として持つ。
- 任意のオプションは `risks`（領域 ID → 負の数）を持ち得る。選択時に当該軸の減点累計に加算する。選択肢の見た目でリスク肢を色分けしない。
- 進捗バーと「現在 / 総数」を表示する。深掘り設問（`weight >= 2`）にはバッジを付与する。
- 最終設問回答後、短い遅延のうえ結果画面へ遷移する。

### 4.4 結果画面

- 四領域それぞれについて、主回答の重み付き集計から素点を算出し、減点を反映した最終スコアを表示する。
- 素点式（設問ごとに独立）: 各軸について、その軸のラベルが選択肢に含まれる設問の重み合計を満点とし、実際にそのラベルを選んだ重みの比率を `GIFT_BASE`〜`GIFT_CAP`（既定 60〜100）に線形変換する。該当設問がない軸の素点は `GIFT_BASE`。
- 最終スコア: 素点に `risks` 由来の減点を軸ごとに加算し、`RISK_FLOOR`〜`GIFT_CAP`（既定 45〜100）に丸める。
- レーダーチャートは軸ごとに独立した半径写像とし、他軸の選択で当該軸の半径を直接縮めない（素点の意味と整合させる）。
- クリック回数（重み付き）による TOP / SECOND 領域を表示する。他領域が「劣る」とは解釈しない旨を UI 文言で配慮する。
- プロフィール型: 素点分布から「バランス寄り」または「ピークあり」を判定し表示する。
- 総括文: 長所の称賛、価値、向いている業務例、活かし方、鼓舞を中心とした固定ロジック文（`buildInspiringSummary`）を表示する。試験合否・人格ランク・接続エラー説明など、利用者の気分を損ねやすい免責長文は結果画面に出さない。
- 詳細開閉: 集計式、思考軸が主回答に現れない設問の列挙、主回答ログ、減点が付いた回答の列挙、生の重み内訳を提供する。

### 4.5 ざっくり目標入力

- 事業・人・個人の3テキストエリア。プレースホルダとヒント文をカテゴリごとに表示する。
- 「目標案を表示する」で目標生成処理を起動する。

### 4.6 目標案の生成

- 入力: 診断の TOP/SECOND、スコア・生カウント・減点累計、ざっくり目標3件。
- 優先動作: Anthropic API（Claude）にプロンプトを送り、JSON（事業・人・個人ごとの `title` / `desc` / `strength_note`）をパースする。
- フォールバック: API 失敗時、または環境変数 `VITE_SKIP_ANTHROPIC` が真のとき、クライアント内の雛形生成（`buildFallbackGoalResults`）により同形の配列を返す。事業4・人4・個人4の計12件を目安とする。
- 成功時 UI では、API 利用有無を利用者に説明する長文バナーを出さない。

### 4.7 目標案一覧

- カテゴリごとにカード表示。各目標の `desc` を編集可能とする。
- いずれかの「達成イメージを生成」で画像プロンプト画面へ進む。

### 4.8 画像プロンプト

- 選択した目標と強みラベル・資質を入力に、英語の画像生成プロンプトを生成する。
- API 成功時はモデル出力を整形して表示。失敗時は英語テンプレート（`buildFallbackImagePrompt`）にフォールバックする。
- コピー、再生成、一覧へ戻るを提供する。

### 4.9 診断のやり直し

- 結果画面から実行可能。スコア、減点、回答ログ、設問インデックスを初期化し、ステップを表紙付きの設問開始に戻す。

### 4.10 ローディング・エラー

- 目標生成・画像生成の待機中はオーバーレイ等で loading を示す。
- クリップボード失敗など、フォールバックで吸収できないエラーはバナーで通知する。

## 5. データ要件

### 5.1 四領域マスタ

`executing` / `influencing` / `relationship` / `thinking` それぞれに、表示ラベル、色、代表資質、短い説明テキストを持つ。

### 5.2 回答ログ

各回答について、設問インデックス、設問文、選択ラベル、主 `domain`、重み、適用 `risks` の有無を保持する。

### 5.3 目標カテゴリ

「事業」「人」「個人」の3カテゴリ。記号・色・プレースホルダは `CATEGORIES` で定義する。

## 6. 外部インターフェース

### 6.1 Anthropic Messages API

- 開発時: ブラウザは同一オリジンの `/api/messages` に POST。Vite が `https://api.anthropic.com/v1/messages` へプロキシし、`x-api-key` と `anthropic-version` を付与する。
- API キー: `app/.env.local` 等に `VITE_ANTHROPIC_API_KEY` または `ANTHROPIC_API_KEY` を設定。`vite.config.js` は設定ファイル所在ディレクトリを基準に `loadEnv` する。
- 利用モデル: 実装時点の定数 `MODEL`（コード参照）。

### 6.2 本番・静的ホスティング

- `vite build` のみでは `/api/messages` は存在しない。本番で Claude を使う場合は別途 BFF またはプロキシの配置が必要。未配置時は目標・画像プロンプトはフォールバックに依存する。

## 7. 非機能要件

### 7.1 体験

- モバイル幅を想定し、メインカラム最大幅は約 480px。
- アクセシビリティ: 表紙に `aria-label`、通知に `role="status"` 等、実装済みの属性を維持する。

### 7.2 セキュリティ

- API キーをリポジトリに含めない。`.env.local` は git 対象外とする。
- クライアントバンドルに API キーを埋め込まない（プロキシ方式を維持）。

### 7.3 パフォーマンス

- 設問遷移はクライアントのみ。外部 API は目標生成と画像プロンプト生成時のみ。

## 8. 制約・非目標

- 本アプリは心理検査や適性試験の代替ではない。結果は設問設計に依存したログの圧縮であり、人事判定・採用決定の唯一の根拠に使うことは想定しない。
- 画像の生成実行は行わない。プロンプトのコピー先（Gemini 等）は利用者の責務とする。
- ユーザー認証、サーバ側への回答永続化、マルチテナントはスコープ外（現実装）。

## 9. 用語

| 用語 | 意味 |
|------|------|
| ギフト / Gift | 本アプリにおける四領域に紐づく才能の比喩 |
| 主回答 | 各設問で選ばれたオプションの `domain` |
| 素点 | 減点前の 60〜100 スケールスコア |
| 減点 | `risks` により最終スコアから差し引かれる値（累計） |
