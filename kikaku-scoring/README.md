# 企画書AI採点エンジン（段階1）

要件定義書 v2.0（2026-09-12）の段階1に対応する最小版。基準セットを外部化し、PDF1件を実APIで全項目採点する。

## 段階1で実装した範囲

- 基準セットの外部化（`criteria/*.json`）。合計点はアプリ側で検算する
- PDF入力（最大20MB・50ページ、パスワード付きは拒否、上限超過は解析前に拒否）
- サーバーがページIDを付与し、抽出テキストとページ画像をIDに紐づける。文字レイヤーのないページは tesseract.js で OCR を試み、失敗時は「画像のみ」として扱う
- OpenAI Responses API（ページ画像入力・構造化出力・応答保存なし）で項目別に採点
- 採点指示と資料本文を分離して渡し、資料内の指示文を実行しない旨をシステム指示に明記
- 出力検証（項目数・重複・点数範囲・ページID実在・引用照合）。照合不能な根拠は項目を保留にし、構造不備は採点失敗として保存しない
- 総合点はアプリ側で加算。保留が1項目でもあれば総合点を出さず小計と理由を表示
- 費用・利用量の記録（`data/usage.json`）と利用上限（`USAGE_LIMIT_USD`）
- 結果・元ファイルの端末内保存（IndexedDB）、同一ファイル・同一基準・同一モデル設定の結果再利用、履歴一覧
- 根拠のページ番号から該当ページ画像を開く

段階2以降（レーダーチャート、比較、PNG出力、人による修正評価、Word/PowerPoint変換）は未実装。

## 起動

```
cp .env.example .env.local   # OPENAI_API_KEY を設定する
npm install
npm run dev                  # http://localhost:3500
```

`AI_PROVIDER=mock` にすると API を呼ばずに疑似結果を返す（UI・検証ロジックの確認用。画面に「モック」と表示される）。

## 構成

- `criteria/` 基準セット（セットID・バージョンで管理。更新時は新バージョンとして追加する）
- `src/lib/pdf.ts` PDF解析・ページID付与・ページ画像描画
- `src/lib/ocr.ts` スキャンページの文字認識
- `src/lib/prompt.ts` 採点指示・資料の渡し方・出力スキーマ
- `src/lib/ai.ts` OpenAI／モック呼び出し
- `src/lib/validate.ts` 出力検証・保留判定・総合点計算
- `src/lib/usage.ts` 利用量台帳・上限
- `src/app/api/` analyze（解析）、score（採点）、criteria、config
- `src/components/` 画面
