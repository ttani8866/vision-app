# /apo-autopilot — APO-AUTOPILOT（アポイント日程調整）

谷会長（新東通信グループ代表取締役／共同ピーアール株式会社 取締役会長）の業務を前提に、複数カレンダー横断で空き枠を抽出しメール下書きまでを一気通貫で実行する。

## 引数（既定値）

入力時に明示された値を優先する。明示なしは既定値を採用し、決定値を実行報告で明示する。

| 引数 | 既定値 | 説明 |
|------|--------|------|
| recipient_name | 必須 | 相手氏名（敬称含む。例: 「山田太郎 様」） |
| company | 任意 | 相手会社名 |
| purpose | 必須 | 用件（1文） |
| recipient_email | 任意 | 宛先メール。不明時は `宛先未確定@kyodo-pr.co.jp` で下書き |
| meeting_mode | online | online / in_person |
| meeting_type | internal | client / internal（バッファと時間帯優先を切替） |
| duration_minutes | 60 | 会議時間 |
| period_days | 14 | 探索期間（最大 28、自動拡張あり） |
| working_hours | 09:00-18:00 | 拡張時 07:30-19:30 |
| buffer_minutes | client=45 / internal=30 | 前後バッファ（meeting_type で決定） |
| num_candidates | 3 | 候補数（最大 5） |
| target_calendars | shinto + kyodopr + 移動 | 対象カレンダーID（複数） |
| signature_mode | both | shinto / kyodopr / both |
| subject_style | new | new / reply（既存スレッド前提の Re:） |
| dry_run | false | true なら下書き保存せず本文プレビューのみ |

## 実行手順

1. 入力確認
   - 必須項目: recipient_name / purpose / recipient_email
   - meeting_type 判定: ユーザー発話に「クライアント」「お客様」「先方」「取引先」等の語が含まれていれば client、それ以外は internal を採用
   - 不足項目がある場合は、不足しているものをすべて1回のメッセージにまとめて質問する（2回に分けない）
     - 例: 宛先・用件いずれも不明 → 「宛先メールアドレスと用件を教えてください」と1回だけ確認
     - 例: 宛先のみ不明 → 「宛先メールアドレスを教えてください」と確認
   - 確認なしでスキップする条件: ユーザーが明示的に dry_run=true を指定した場合のみ、本文プレビューを先に提示してから不足項目を確認する

2. カレンダー予定の取得
   - `mcp__095f26ea-...__list_calendars` で対象カレンダーIDを取得
   - target_calendars で指定された各カレンダーに対し `mcp__095f26ea-...__list_events` を呼び、今日〜period_days 後の全予定を取得
   - 終日イベントと tentative 扱いも対象（ブロックとみなす）
   - 全カレンダーの予定をマージしてビジー時間帯を構築

3. 空き枠の抽出
   - 対象: 平日（土日除く）、working_hours 内
   - 条件: duration_minutes 連続で空き、かつ前後 buffer_minutes の予定なし
   - 0件の場合は period_days を 28 まで自動拡張して再試行
   - それでも0件なら working_hours を拡張帯（07:30-19:30）に変更して再試行
   - これでも0件ならユーザーに状況報告し相談

4. 候補の選定と並べ替え
   - 時間帯の優先順位を meeting_type で切り替える
     - meeting_type=client: 10:00〜16:00 の枠を最優先（朝一・夕方は次点）
     - meeting_type=internal: 朝一（09:00〜10:00）と夕方（16:00〜18:00）の枠を最優先（中間帯は次点）
   - 同優先帯では、余裕の多い枠（前後2時間以上空き／終日空き）を上位
   - さらに同条件なら早い日付を優先
   - num_candidates 件に絞る
   - JST タイムゾーンを明示

5. プレーンテキスト整形
   - 表形式は使わない
   - フォーマット例:
     ```
     【日程候補（JST）】
     ・4月30日（木）午前 10:00〜11:00
     ・5月1日（金）午後 14:00〜15:00
     ・5月7日（木）午前 9:00〜10:00
     ```

6. メール文生成
   - `templates/email_template.md` の本文構造を採用
   - signature_mode に従い `templates/signature.txt` から該当ブロックを差し込む
   - subject_style=new: `【日程のご提案】{purpose}の件`
   - subject_style=reply: `Re: {purpose}／日程候補`
   - 確定文言は「ご返信いただき次第、こちらで仮押さえし、最終確認のうえ確定いたします」（即確定の言い回しは禁止）

7. Web会議URLの扱い
   - meeting_mode=online: 本文中に「会議URLは確定後にお送りいたします」と明記
   - meeting_mode=in_person: 場所未定なら「場所のご希望がございましたらお知らせください」、決定済みなら省略
   - 自動発行はしない（秘書側で発行する想定）

8. Gmail 下書き保存
   - dry_run=false の場合のみ `mcp__f60e8ec4-...__create_draft` を呼ぶ
   - To: recipient_email（不明時は `宛先未確定@kyodo-pr.co.jp`）
   - Subject: 6.で生成
   - Body: 6.で生成
   - 送信は絶対にしない（下書き止め）

9. 完了報告
   - 抽出された総空き枠数、採用候補数、適用引数（特に既定から変更した値）、下書き保存有無を報告
   - dry_run=true なら本文プレビューを提示し、確定指示を待つ
   - 宛先がプレースホルダ（`宛先未確定@kyodo-pr.co.jp`）の場合は人手置換が必要である旨を必ず明示

## 入力例

- 「クライアントのABC商事 山田様とAI研修ご提案の件で日程調整して」（→ meeting_type=client、バッファ45分、10〜16時優先）
- 「来週の社内ミーティング候補3つ出して。60分」（→ meeting_type=internal、バッファ30分、朝夕優先）
- 「[相手名]様にメール下書きまで。dry_run で先に本文確認」
- 「PR業界のお客様向けなので signature_mode=kyodopr で」

## 出力物

- 日程候補（プレーンテキスト）
- Gmail 下書き（dry_run=false 時のみ）
- 適用引数の決定値リスト

## 構成ルール

- 日本語、敬体
- ボールド（**）禁止
- 候補は表形式を使わずプレーンテキスト
- 差出人氏名は「谷 鉄也」（哲也と書かない）
- JST 明示
- 送信は絶対にしない（下書き止め）

## 注意事項

- バッファ既定: client=45分、internal=30分。クライアント打合せで30分しか取らないと前後の予定にぶつかった際の調整余裕が消える
- 時間帯優先: client は 10:00〜16:00（落ち着いた時間帯に外部対応）、internal は朝一・夕方（コアタイムは外部対応に空けたい）。優先帯で枠が0件なら次点帯から補充する
- 対象カレンダーは新東通信＋共同ピーアール＋移動ブロックの3本が最小構成（兼務のため片肺カレンダーでは過剰提案になる）
- 上場企業（共同ピーアール）のインサイダー情報を含む可能性のある用件は明示警告
- API キー・認証情報をファイルに含めない
- recipient_email が空欄のままの下書き保存は Gmail 側で警告される。プレースホルダ運用とし、送信前に必ず人手で置換する
- 確定の言い回しは「仮押さえ＋最終確認」のワンクッションを必ず入れる
