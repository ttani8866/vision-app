# ばえめし リール運用パッケージ（ハイブリッド体制版）

作成日: 2026-08-16
対象: 週3本・月12本のリール制作
体制: 企画・店舗選定・アポ・キャプション・投稿は内製／撮影・編集は外部委託

---

## 1. 役割分担

| 工程 | 担当 | 月間工数 | 備考 |
|---|---|---|---|
| 店舗選定・企画 | 内製 | 6時間 | ジャンル配分表に従う |
| 取材アポ・日程調整 | 内製 | 6時間 | 依頼文テンプレートあり（第7章） |
| 撮影 | 委託 | ー | 週1日、1日4店舗 |
| 編集 | 委託 | ー | 本仕様書に準拠 |
| キャプション作成 | 内製 | 3時間 | テンプレートに流し込み |
| 投稿・コメント返信 | 内製 | 10時間 | 日次20分 |

内製工数は月15時間（約0.1人月）。撮影日には内製担当が同行するか、店舗リストと撮影指示書を事前に渡す形のいずれかを選ぶ。初月は同行を推奨する。

## 2. リール制作仕様（委託先へ渡す部分）

### 2-1 基本仕様

| 項目 | 指定 |
|---|---|
| 尺 | 15〜25秒（標準20秒） |
| 比率 | 9:16（1080×1920） |
| 形式 | MP4、H.264 |
| フレームレート | 30fps（スローモーション用カットのみ60fps撮影） |
| 音声 | 環境音を残す。BGMは編集で付与 |
| テロップ | 焼き付け納品 |
| 納品期限 | 撮影から3営業日以内 |

### 2-2 20秒の標準構成

| 秒数 | 内容 | 指定 |
|---|---|---|
| 0.0〜2.0 | フック | 第3章の5型からいずれかを指定。テロップは画面の上1/3、最大18文字 |
| 2.0〜8.0 | 主役の一皿 | 寄りで2〜3カット。動きのカットを必ず2つ以上入れる |
| 8.0〜15.0 | 店の文脈 | 外観、店内、職人の手元から1〜2カット |
| 15.0〜18.0 | 価格とメニュー名 | テロップで明示。税込表記 |
| 18.0〜20.0 | CTA | 「保存して銀座で使って」＋アカウント名。固定カット |

冒頭2秒でスクロールを止められなければ以降は見られない。ここに最も時間をかけること。

### 2-3 必須カット（1店舗あたり）

以下は全店舗で必ず撮影する。編集で使わないカットがあっても構わないが、撮影漏れは差し戻しとなる。

1. 店の外観または入口（引き、1〜2秒）
2. 主役の一皿が置かれる瞬間、または真俯瞰
3. 動きのカット2種以上。以下から選ぶ
   - 湯気が立つ
   - 持ち上げる（麺、チーズ、肉）
   - 断面を割る、崩す
   - ソースやスープを注ぐ
   - とろける、溶ける
4. 箸またはカトラリーで口へ運ぶ手前まで（口元は映さない）
5. 店内の雰囲気（引き、1カット）
6. メニュー名と価格のテロップを載せるための静止カット

### 2-4 テロップ規格

- セーフエリア: 上端から10%、下端から20%は使用しない（Instagramのインターフェースに隠れるため）
- フォント: 太めのゴシック体で統一。全投稿で同一のものを使う
- 色: 白文字＋黒フチ、または黒帯＋白文字。読めることを最優先する
- 1画面あたり最大18文字。2行までとする
- フックのテロップは0.0秒から表示する。フェードインさせない

### 2-5 BGM

- 商用利用可能な音源、またはInstagramの音源ライブラリから選ぶ
- トレンド音源は発見面で有利になるが、権利関係が確認できないものは使わない
- 料理の音（焼ける音、麺をすする音、注ぐ音）が入るカットではBGMを下げる。シズルは音の要素が大きい

### 2-6 やらないこと

- 過度なエフェクト、トランジション。カットは基本的につなぐだけ
- 顔出し、実食リアクション。ばえめしは店を主役にする方針のため
- 手ブレのまま納品しない。ジンバルまたは手ブレ補正を使う
- 暗い店内でノイズが乗った映像。クリップライトを使う
- 他アカウントの映像やテンプレートの流用

## 3. 冒頭2秒のフック5型

企画時に内製側がどの型かを指定し、撮影指示書に書く。

| 型 | テロップ例 | 撮影上の指定 |
|---|---|---|
| 価格ギャップ型 | 銀座でこれ、1,200円です | 価格の安さが伝わる盛りの一皿を最初に見せる |
| ビジュアル衝撃型 | （テロップなし、無言で断面） | 最も派手な動きのカットを冒頭に置く |
| 場所の意外性型 | このビルの地下、知らないと入れません | 入口の引きから始める |
| 権威型 | 創業100年、銀座の◯◯ | 看板や店名が読めるカットから始める |
| 疑問型 | 銀座で一番予約が取れない店 | 店内の引きから始める |

月12本の配分は、価格ギャップ型3、ビジュアル衝撃型3、場所の意外性型2、権威型3、疑問型1を目安とする。第1期で型ごとの実測を取り、第2期で配分を変える。

## 4. キャプションテンプレート（内製側）

全投稿でこの型を崩さない。冒頭3行は固定文言とする。

```
↓店舗詳細↓ 銀座のばえめし、毎週3本更新
💡他の投稿はこちら→ baemeshi_official
行きたいと思ったら右の「…」から保存！

【店名】
（店舗の公式インスタID）
📍住所
🚃最寄駅と徒歩分数
📞電話番号
🕑営業時間・定休日
🍽️メニューと価格（税込）
💳支払方法

（2〜4行。この店が銀座でしか成立しない理由を書く）
（1行。第三者に送る動機の一文を入れる）

#銀座グルメ #銀座ランチ #ばえめし #（ジャンル） #（店名）
```

第三者に送る動機の一文は、シェア中央値0という現状を変えるための項目である。以下のような形にする。

- 来週の会食、ここで決まりでは
- 銀座で待ち合わせる人に送ってあげてください
- 親を連れて行くならここです

ハッシュタグは5個で固定する。銀座軸2個（#銀座グルメ #銀座ランチ または #銀座ディナー）、ブランド1個（#ばえめし）、ジャンル1個、店名1個。

## 5. 投稿前チェックリスト

投稿ボタンを押す前に、内製担当が以下を確認する。1つでも欠けていれば投稿しない。

- [ ] 冒頭2秒にフックのテロップが入っているか
- [ ] 動きのカットが2つ以上入っているか
- [ ] 価格が税込で明示されているか
- [ ] 18〜20秒にCTAカットがあるか
- [ ] テロップがセーフエリアの内側にあるか
- [ ] キャプション冒頭3行が固定文言になっているか
- [ ] 住所・最寄駅・営業時間・定休日・支払方法が揃っているか
- [ ] 第三者に送る動機の一文が入っているか
- [ ] ハッシュタグが5個か
- [ ] 前回投稿から24時間以上空いているか
- [ ] 店舗の公式アカウントをメンションしたか

最後の項目は、店舗側にシェアしてもらう可能性を作るためのものである。店舗がストーリーズで再投稿すれば、そのフォロワーへの到達が生まれる。

## 6. 撮影日の回し方

週1日、4店舗を1日で回す。銀座・新橋・築地・有楽町は徒歩圏に収まるため成立する。

標準スケジュール例。

| 時刻 | 内容 |
|---|---|
| 10:30 | 1店舗目（モーニングまたは仕込み時間の取材） |
| 11:30 | 移動 |
| 11:45 | 2店舗目（ランチ営業開始直後。混雑前） |
| 13:00 | 移動、休憩 |
| 14:30 | 3店舗目（アイドルタイム。カフェ・スイーツ向き） |
| 16:00 | 移動 |
| 17:30 | 4店舗目（ディナー営業開始直後） |

各店舗の撮影は30〜40分を上限とする。店舗の営業を妨げないことが最優先であり、リピート取材の可否に直結する。

ランチ・ディナーのピークタイム（12:00〜13:00、19:00〜20:30）は撮影を入れない。

```

・掲載形式: リール動画（20秒程度）＋店舗情報
・撮影所要時間: 30〜40分程度
・撮影希望日: ◯月◯日（◯）◯時頃　※ご都合に合わせて調整いたします
・費用: 当方でお支払いいたします（お代はこちらで負担いたします）

ピークタイムを避けての撮影を予定しております。
```

掲載前確認を明記しておくと承諾率が上がる。また費用をこちらが負担することを先に書くことで、営業の類ではないことが伝わる。

## 8. 第1期に記録するもの

委託先には求めず、内製側で毎週記録する。第1期の目的は単位経済の確定であるため、以下がないと第2期の目標が置けない。

| 記録項目 | 取得元 | 頻度 |
|---|---|---|
| リール1本あたりの総リーチ | 投稿インサイト | 投稿ごと |
| うち非フォロワーリーチ | 投稿インサイト | 投稿ごと |
| 投稿経由フォロー | 投稿インサイト（follows） | 投稿ごと |
| 保存数・シェア数 | 投稿インサイト | 投稿ごと |
| 使用したフックの型 | 手動記録 | 投稿ごと |
| ジャンル | 手動記録 | 投稿ごと |
| フォロワー年齢構成 | follower_demographics | 月次 |
| 広告のCPFと配信年齢 | 広告インサイト（権限復旧後） | 週次 |

フックの型とジャンルを手動で記録しておくことが重要である。これがないと、伸びた投稿がなぜ伸びたのかを後から分解できない。既存の日次レポートスクリプトに追記して自動化する。
