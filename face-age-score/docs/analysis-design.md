# FACE AGE SCORE — 写真AI分析 設計書 v0.1（2026-09-15）

## 1. 目的

ユーザーが入れた正面の顔写真から、肌・輪郭の状態を10の評価軸で採点し、
課題を挙げ、改善アドバイス（守り＝ホームケア／攻め＝美容施術）につなげる。
出力はすべて「推定・参考評価」であり、医療診断ではない。

## 2. 全体フロー

```
写真を選ぶ（slot-upload.js）
  → 長辺1400pxに縮小した JPEG data URL をブラウザ内に保持
  → 「写真をAI分析する」ボタン（analyze.js）
  → POST /api/analyze { image }   ……… server.js（Node）
  → Claude Messages API（画像入力＋構造化出力）
  → 分析JSON（§4）
  → 画面へ反映（§5）／ブラウザ内に保存（前回比の計算に使う）
```

- サーバーは `face-age-score/server.js`。静的ファイル配信と `/api/analyze` を兼ねる。
- APIキーは環境変数 `ANTHROPIC_API_KEY`（または `face-age-score/.env`、git管理外）から読む。
- キー未設定時はデモ結果（`mock-analysis.json`）を返し、画面に「デモ結果」と明示する。
- モデルは `claude-opus-5`（`FAS_MODEL` で変更可）。構造化出力で JSON を保証する。

## 3. 評価軸（10軸・10点満点）

レーダーチャートの並び順と同じ。各軸は 0〜10 点、目標帯は 8.5〜9.0。

| key | 軸 | 見るところ | 高得点の目安 |
|---|---|---|---|
| tsuya | ツヤ | 頬・額の光の反射、皮脂と水分のバランス | 均一で自然な光沢 |
| hari | ハリ | 頬の丸み、皮膚の張り、たるみの兆候 | 頬が下がらず輪郭が締まる |
| kime | キメ | 皮膚表面の細かさ、粗さ | 表面が滑らかで均一 |
| keana | 毛穴 | 鼻・頬の毛穴の目立ち、開き、黒ずみ | ほぼ目立たない |
| kusumi | くすみ | 全体の透明感、黄ぐすみ、色ムラ | 明るく均一な肌色 |
| shimi | シミ | 色素沈着の数・濃さ・範囲 | ほぼ見当たらない |
| shiwa | シワ | 額の横ジワ、眉間、目尻の小ジワ | 表情を止めた状態で目立たない |
| mebukuro | 目袋 | 目の下の膨らみ、影、クマ | 膨らみ・影がない |
| hourei | ほうれい線 | 鼻横から口角への溝の深さ | 溝がほぼ見えない |
| faceline | フェイスライン | 顎の輪郭のシャープさ、二重顎、左右差 | 輪郭が明瞭 |

採点ルール（プロンプトで指示）
- 写真から見える範囲のみで採点し、断定しない。
- 照明・角度・解像度で判断が難しい軸は控えめな中央値（6〜7）に寄せ、`confidence` を下げる。
- 総合スコア（100点満点）は 10軸の単純平均 × 10 を基本とし、目袋・ほうれい線・シワなど「年齢印象」に効く軸を重く見る。

## 5. 画面への反映

| 画面要素 | 反映内容 |
|---|---|
| ヘッダー日付 | 分析日 |
| 総合スコア | `total_score`、前回分析があれば前回比、見た目年齢・肌年齢、改善率（前回比の%） |
| 総評 | `summary` |
| 顔ゾーン診断 | 6ゾーンのチップ色・スコア・詳細パネル（`zones`） |
| 評価バランス | 10軸レーダーの実線を `axes` で再描画、最低スコア軸を赤で強調 |
| 改善優先順位 TOP3 | `issues`（現在→目標） |
| AI診断コメント | ① `summary`＋写真の状態 ② 良好な点（`strengths`、前回があれば改善軸） ③ 課題（`issues`） ④ `priority_order` ⑤ 注意点（`cautions`） |
| 改善アドバイス｜守り | 朝・夜のルーティン（`home_care`） |
| 改善アドバイス｜攻め | `procedures`（優先度順） |
| 確度表示 | `confidence`／`photo_quality` を分析ボタン下に表示。低確度なら再撮影を促す |

据え置く要素：おすすめ商品、おすすめクリニック、改善スケジュール、スコア推移グラフ、Before/After の数値。
これらは商品・クリニックの台帳や履歴DBが必要で、写真1枚の分析では決まらないため次段階とする。

## 6. 前回比・履歴

- 分析結果は `localStorage` に `analysis:latest` と `analysis:previous` として保存する。
- 2回目以降は前回との差分で「前回比」「改善率」「改善された点」を出す。
- 本番では ScoreSnapshot 相当のテーブルにユーザー別で保存する（サーバー側DBは未実装）。

## 7. 安全・法務

- 出力は「推定・参考評価」と明示し、疾患名の断定や治療の指示はしない。
- 皮膚の異常（急な変化・出血・強い炎症など）が疑われる場合は受診を促す文言のみ返す。
- 写真は分析リクエストの中でのみ API に送り、サーバーには保存しない。
- APIキーはファイルに書かず、環境変数または git 管理外の `.env` から読む。
